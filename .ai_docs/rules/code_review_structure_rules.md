# 结构性代码审查规则

状态：AI 初稿，待 wentZh2004 确认。确认前本文只提供建议，不构成强制规范。

审查只针对当前改动，并以代码证据为依据。不要把个人偏好包装成结构性问题。

## 检查维度

- 模块职责是否清晰，依赖方向是否合理。
- 是否引入了不必要的耦合、重复数据流、转发文件或过度抽象。
- 页面、布局、组件、内容、工具和插件之间的边界是否仍然可理解。
- 静态生成逻辑是否错误地依赖浏览器运行时；客户端交互是否被错误地放入静态层。
- 内容 schema、locale、草稿过滤和公共组件接口是否保持一致。
- 改动是否扩大了计划范围，或改变了用户未确认的公共行为。
- 涉及交互时，是否出现明显的键盘、语义 HTML、焦点或移动端结构问题。

## 输出要求

每条问题包含：严重级别、文件和符号、代码证据、影响和建议方向。没有证据的问题标记为待确认，不直接判定为缺陷。审查 Agent 只报告，不修改代码。
