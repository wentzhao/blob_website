# 代码规则

## 基本原则

- 先理解现有页面、内容和组件边界，再修改代码。
- 优先复用已有依赖和工具；新增依赖必须说明必要性。
- 保持修改范围与需求一致，不为假设中的未来需求增加抽象。
- 变量、函数和组件名称使用能表达业务含义的英文名称；注释解释原因，不重复代码。

## Astro、Svelte 与内容

- Astro 组件优先承担静态页面组合和服务端数据准备。
- 只有需要浏览器状态、事件或生命周期时才使用 Svelte；避免为静态内容引入客户端 JavaScript。
- 文章和 spec 内容必须遵守 `src/content.config.ts` 的 schema。
- 页面筛选、排序和 locale 回退逻辑优先复用 `src/utils/content-utils.ts` 和既有 i18n 工具。

## 样式与配置

- 优先使用已有 CSS 变量、样式文件和组件局部样式。
- 不在多个组件复制同一套站点级样式或配置逻辑。
- 站点、主题、评论和许可设置集中在现有配置入口；不要在页面中散落硬编码配置。

## 修改边界

- 如果实现需要改变内容 schema、路由约定、公共组件接口或模块职责，先停止并说明设计影响。
- 不将简单逻辑拆成大量仅转发调用的文件。
- 不删除现有安全处理、草稿过滤、HTML 清洗或可访问性行为，除非用户明确要求并完成替代验证。
