一个好的知识库不需要从完整开始，只需要让下一次查找比上一次更容易。

## 为什么从 Markdown 开始

文章以 Markdown 文件保存，内容和界面彼此独立。写作时可以专注于结构，发布时再由 Astro 在构建期生成页面。

:::tip
把稳定的结论写进文章，把临时的想法留在草稿里。草稿不会进入公开归档和搜索索引。
:::

## 一个小例子

```ts
type Note = {
  title: string;
  category: string;
};

const note: Note = {
  title: "从一篇笔记开始",
  category: "技术笔记",
};
```

当内容数量增加，分类和目录会成为检索入口。对于一个简单的索引，时间复杂度可以写成 $O(n)$；如果进一步建立索引，查找可以接近 $O(\log n)$。

$$
T(n) = O(\log n)
$$

> 记录不是为了证明自己记得，而是为了让未来的自己少走一段弯路。

| 内容 | 入口 | 状态 |
| --- | --- | --- |
| 技术笔记 | 分类目录 | 已启用 |
| 项目实践 | 分类目录 | 待添加 |

后续可以从[归档页](/archives/)浏览全部文章，也可以直接使用顶部搜索。
